# 首个 MVP：验收与客户端接入

本轮只修改代码，没有启动应用、运行测试或打包。以下项目由人工验收后确认，不代表已经通过。

## 使用范围

- 单人、本地管理公开的 GitHub / Gitee 仓库；Token 仅供控制端发布。
- 仅稳定版，版本号使用三段数字（如 `1.2.0`），新版本必须高于本地和远端已有稳定版本。
- macOS：arm64 / x64 / universal，DMG / PKG / ZIP。
- Windows：x64 / arm64，EXE / MSI / ZIP。
- Android：arm64-v8a / armeabi-v7a / x86_64 / universal，仅 APK。
- 同一版本最多 20 个附件，不能有重名文件或重复的平台＋架构＋包类型组合。
- 文件后缀只能辅助选择平台与包类型，无法证明实际架构；发布者必须确认构建目标正确。
- 每次发布的清单仅包含本次选择的附件，不会自动继承上一版附件。需要同时更新多个平台时，一次选齐。
- 历史列表只展示本机记录，不自动拉取完整远端历史。重新添加已有仓库能读取当前版本，但不会恢复完整历史。

## 人工验收清单

请使用专用的公开测试仓库，不要在正式更新仓库中测试故障。

- [ ] 重启应用后，产品、历史、分支和 Token 保留，Token 默认隐藏、眼睛按钮可以切换。
- [ ] Gitee 发布一个新版本：Release、所有附件、`.release-hub/updates/stable.json` 和本地历史均一致。
- [ ] GitHub 完成同样流程。未完成此项前，不宣称 GitHub 已实测可用。
- [ ] 版本页点击“校验客户端下载”，逐个选择已发布的目标，确认下载、大小、SHA-256 校验通过。
- [ ] 发布更高版本后，再次打开下载校验，显示新版及新版附件。
- [ ] 重复版本、低版本、非法版本号、重复文件名、重复构建目标、错误后缀被拒绝，不新增 Release。
- [ ] 文件选择后移走文件，或选择空文件：发布被阻止，不新增 Release。
- [ ] 连续点击发布不会产生多份发布；发布中编辑、关闭弹窗、普通退出被阻止。
- [ ] 测试仓库中上传期间断网：保留发布阶段和处理建议，不显示成功、不新增本地历史。
- [ ] 下载链接失效、返回错误页面或附件被替换时，下载校验不显示通过。
- [ ] 最小窗口下能看到操作按钮；长文件名不挤压架构下拉框，悬停能查看完整文件名；多个附件时弹窗可滚动。
- [ ] 最终由你打包验证：生产应用不自动打开开发工具，图标正常，数据位于生产 userData 目录，不读写开发数据库。

## 发布失败如何处理

1. 尚未创建 Release：修复文件、版本号、权限或网络问题后重试。
2. 已创建 Release、清单尚未写入：到平台核对失败的 Release、附件和标签。确认它们属于本次失败操作后，手动处理，再重试；不要删除已有正常版本。
3. 提示清单写入结果未确认：先检查 `.release-hub/updates/stable.json` 和附件。请求超时不代表远端未成功，不要直接重复发布或删除。
4. 远端发布成功但本地历史保存失败：以远端为准，不重复发布。检查磁盘空间，保留错误信息；本 MVP 不提供本地历史恢复功能。

应用不自动删除远端内容、不自动回滚、不支持断点续传。普通退出有保护，但断电、系统强制退出仍可能留下部分发布。跨设备同时发布不属于本 MVP 支持范围；清单写入前会再次检查变化并使用文件 SHA 防止覆盖已观察到的更新。

## 客户端读取约定

客户端不需要发布 Token。公开仓库不一定代表附件实际可匿名下载，以“校验客户端下载”的结果为准。

1. 获取仓库默认分支。
2. 用匿名 Contents API 读取该分支的 `.release-hub/updates/stable.json`，将响应的 `content` 从 Base64 解码为 JSON。
   - GitHub：`https://api.github.com/repos/{owner}/{repo}/contents/.release-hub/updates/stable.json?ref={branch}`
   - Gitee：`https://gitee.com/api/v5/repos/{owner}/{repo}/contents/.release-hub/updates/stable.json?ref={branch}`
3. 将 `version` 按三段数字比较，不能用字符串大小比较；不高于客户端当前版本则不更新。
4. 从 `assets` 中按 `platform`、`architecture`、`packageType` 精确选择。若客户端希望兼容 universal，应由客户端显式实现候选策略，不可随意取第一个附件。
5. 下载 `downloadUrl`，检查实际字节数等于 `size`，SHA-256 等于 `sha256` 后，交给客户端自身的安装流程。

清单字段：`schemaVersion: 1`、`channel: stable`、`version`、`tag`（`v` 加版本号）、`publishedAt`（毫秒时间戳）、`notes`、`assets`。附件包含 `id`、`fileName`、`platform`、`architecture`、`packageType`、`size`、`sha256`、`downloadUrl`。旧清单可能没有 schemaVersion / channel。

该格式是 ReleaseHub 自定义协议，不是直接接入任意自动更新框架的通用配置。客户端检查、安装、签名验证及系统权限由客户端负责；SHA-256 用于核对文件完整性，不替代安装包签名。匿名 API 有平台限流，客户端应合理控制检查频率。

暂不扩展：私有仓库客户端鉴权、远端完整历史同步、版本编辑删除、灰度发布、强制更新、差分包、多用户发布锁、自动回滚。
