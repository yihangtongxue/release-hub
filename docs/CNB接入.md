# CNB 发布接入

CNB 是腾讯的云原生开发平台，官网：[cnb.cool](https://cnb.cool/)。本次已编写接入代码，尚未启动应用、运行测试、打包或使用真实 Token 发布；以下步骤和验收由使用者执行。

## 配置

1. 更新项目依赖（新增 `isomorphic-git`），然后按原来的方式启动 ReleaseHub。
2. 在 CNB 创建公开的安装包发布仓库。可以只放安装包与更新清单，业务源码继续留在原仓库。支持 `https://cnb.cool/组织/仓库` 和多级组织地址。
3. 按 [官方访问令牌指引](https://docs.cnb.cool/zh/guide/access-token.html) 创建 Token，允许访问目标仓库，并授权 `account-profile:r`、`repo-basic-info:r`、`repo-code:rw`、`repo-release:rw`。账号至少需要仓库开发者权限。账号验证成功仅说明身份有效，仓库和写权限还会在对应操作中检查。
4. ReleaseHub → 设置 → CNB → 填 Token → 验证并保存。卡片提供官网、Token 指引和免费额度入口；Token 沿用本机加密保存机制。
5. 设置新产品发布分支（例如 `release-hub`），使用允许直接写入的分支；受保护或锁定的 CNB 分支会被拒绝。已有产品仍使用创建时保存的分支。
6. 新增产品 → 选择 CNB → 填仓库根地址 → 确认初始化。空仓库会创建分支并提交 `.release-hub/manifest.json`；非空仓库缺少指定分支时会从默认分支创建，不删除业务文件。
7. 进入版本管理，选择签名策略、版本、平台/架构/包类型和安装包，发布后用“校验客户端下载”核对真实下载的大小与 SHA-256。

## 大文件与免费额度

- 本地预检要求单个附件 **小于 5,000,000,000 字节**。这是依据 [CNB 官方附件插件说明](https://cnb.cool/cnb/plugins/market/-/blob/c5a2ff7c17a6a8ddb921c205d50c8e3e5758031b/plugins/cnbcool/attachments/README.md) 设置的保守限制，不声称是平台全部上传方式的绝对上限。
- 界面检查选择文件时的大小；后端在创建/修改 Release 前检查磁盘实际文件、非空、大小、文件名、重复目标、版本与签名。文件在选择后被替换也不能绕过大小限制。
- 按 [CNB 价格说明](https://docs.cnb.cool/zh/pricing.html)，对象存储免费额度为每个顶层组织 100 GiB，与制品、LFS、图片及其他附件共享。以组织控制台实时额度和平台现行规则为准；应用不会购买资源或启用付费预算。
- 应用不估算组织剩余额度；余额不足、权限不足、限流和上传过期由 CNB 返回错误。免费额度不是无限存储或无限服务保证。
- 上传使用磁盘 Blob，计算 SHA-256 后流式上传；获取预签名地址、PUT 文件、调用确认接口、核对远端大小，再检查匿名下载入口。上传超时为 1 小时，不支持断点续传，失败需重新上传。

## 覆盖与失败处理

同版本确认覆盖后，删除该版本整个旧 Release 及其全部附件，再创建同版本 Release，上传本次选择的全部文件。远端附件使用本地原始文件名，保留大小写和扩展名，不生成随机名。之前遗留的随机名附件也随旧 Release 一并清理；其他版本不受影响，对应 Git 标签及其代码提交保留。平台自动提供的 Source code 下载项仍由平台显示，不属于上传附件。

文件大小、版本、构建目标和签名仍在删除前完成校验。全部新附件上传并确认后更新 Release 说明，最后提交 `stable.json`，再保存本机发布记录。清单写入前和 Git 提交时检查内容是否变化，远端仅使用非强制推送。

覆盖期间旧附件可能无法下载，失败可能留下部分新 Release 或附件，不自动恢复旧附件；修复问题后重新发布同版本并确认完整覆盖。若提示清单写入结果未确认，应先检查远端清单，不能把超时当作没有成功。同版本同名文件的公开链接可能不变，但内容和校验值会变化；客户端须重新读取清单并校验实际下载，旧缓存不能视为新文件。不支持跨设备发布锁或断点续传。

CNB 管理文件通过内置 JavaScript Git 库提交，无需额外安装 Git；临时仓库不检出、不执行仓库内容，结束后删除。只写两个管理文件，不强制推送。为避免拉取大型代码库占用过多内存，Git 响应上限为 256 MiB，建议使用独立发布仓库；安装包本身上传到 Release，不进入 Git 历史。

## 客户端

匿名 GET（组织路径可有多级，分支参数需 URL 编码）：

```text
https://cnb.cool/{组织路径}/{仓库}/-/git/raw/{发布分支}/.release-hub/updates/stable.json
```

直接读取响应 JSON，再按现有更新协议选择构建目标。公开仓库的管理 OpenAPI 仍可能返回 401；发布端可以使用 Token 调用 Contents API，但客户端使用上述公开 raw 地址，不提供发布 Token。

`downloadUrl` 保存 `https://cnb.cool/{组织路径}/{仓库}/-/releases/download/{tag}/{远端附件名}` 的公开稳定入口，不能使用需要认证的 `api.cnb.cool` 管理入口。下载时跟随到对象存储的重定向；不保存会过期的对象存储签名 URL，也不使用有限次数的分享链接。客户端应采用清单中的原始 `fileName` 保存文件，核对大小、SHA-256 和产品要求的签名，再安装。软件如何检查、安装和回滚仍由客户端实现。

## 人工验收

- [ ] 升级后 GitHub/Gitee 产品、分支、签名设置、Token 和历史附件保留；CNB 连接和产品重启后保留。
- [ ] 正确 Token 验证账号；错误/过期 Token、未授权仓库、私有仓库、受保护分支均得到明确错误。
- [ ] 空公开仓库、非空仓库缺失指定分支、多级组织地址均可初始化；业务文件保留。
- [ ] 发布超过 100 MB 且小于 5 GB 的真实安装包，远端附件、清单和本地历史一致；匿名完整下载通过大小和 SHA-256 校验。
- [ ] 超限、空文件、选择后替换成超限文件、重复构建目标及签名失败，在远端修改前被阻止。
- [ ] 同版本取消覆盖不改远端；确认覆盖后远端仅保留本次原名附件，旧随机名附件消失，说明、清单和本地历史一致；本地同版本只保留一条记录，较低版本仍拒绝。
- [ ] 上传中断、第二个附件失败、配额不足、分支写入被拒绝时不显示发布成功；明确提示旧附件已删除和恢复方式，不能声称旧附件仍可用（清单提交结果不明时先人工核对）。
- [ ] 上传过程中他处修改清单：本次不能覆盖该更新；重试时重新检查并确认。
- [ ] 官网/Token/额度按钮在系统浏览器打开；最小窗口仍能操作设置和发布界面。

API 实现依据：[CNB OpenAPI](https://api.cnb.cool/)、[官方 Swagger](https://api.cnb.cool/swagger.json)。未经过上述真实账号验收前，不代表已验证所有平台行为。

## 已上传却提示匿名校验 401

`api.cnb.cool` 管理接口即使访问公开仓库也可能要求登录。附件公开下载必须走 `cnb.cool` 网站入口，客户端清单读取走网站 Raw 地址。不能通过给安装客户端添加发布 Token 来解决。

2026-09-12 针对现有公开附件进行了只读排查：网站 HEAD 返回 200，GET 跳转后分段下载返回 206，管理 API 匿名请求返回 401；公开管理文件 Raw 读取返回 200。这仅验证入口及部分字节读取，不代表完整发布和全文件 SHA-256 已验收。

相关修复位于 Electron 主进程，更新代码后需重启开发进程，仅刷新窗口不会替换已加载的主进程代码。重试同版本需重新确认覆盖，整个旧 Release 和已经上传的附件会被替换。
